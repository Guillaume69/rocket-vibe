# GTK and web screen coverage matrix

GTK is the visual and interaction reference for the Vibez web client. This audit inventories **41 unique route/control families** and **302 conditional source states**. The expanded local inventory has 397 records, including observed runtime variants and aliases; those records are not 397 separate screens. Permission, capability, receipt, error and data variants often use the same container. A rendered family does not imply every such variant was rendered.

The current local index contains **75 state IDs with both native and browser captures**. Counts below include retained language/viewport variants and earlier baselines. They are evidence counts, not a completion percentage. No absent screenshot is treated as pixel equivalence.

## Explicit mappings and limits

- Browser one-origin/one-account replaces GTK's multi-server rail and Accounts switching. Native keyring, background/tray/updater and browser storage/service-worker/diagnostics are different platform surfaces. Across-room search and thread-list browser routes are recorded separately because the current native Vibez primary buttons are hidden.
- GIF is capability-gated and not exposed by the native capture fixture. Its browser functional fixture and native source inspection do not qualify an unrendered native chooser.
- The native and browser spotlight inherit the server's first100-user directory limit. Names outside that directory cannot be found by this existing API; the audit did not invent a public protocol or silently call that limitation complete.
- Protected image and audio UI is rendered using deterministic fixture media. Physical microphone/camera/speaker behavior, noise suppression, device permutations and all permission/refusal combinations are not inferred from passing byte or RTP checks. Native VP8 playback/image reduction are rendered; video reduction is a browser-only extra, and bare-Xvfb fullscreen WM geometry remains unqualified.
- Screen selection is owned by the operating system or browser. Web 'getDisplayMedia' cannot embed the browser's source chooser inside the application popup. The retained application share popup remains the requested interaction; no consent policy was weakened.
- Native GTK and browser font rasterizers, platform chrome and intrinsic borders differ. Exact structure, native captions, controls, defaults, role/read-only states and bounded geometry were compared; pixel identity is not asserted.
- Passwords, entered codes, QR/key material, recovery bags, invitation/API credentials and private excerpts are masked or omitted. The native redaction helper occasionally hides a neighbouring copy-button caption; widget TSV/source proves those actions, and the masked pixels do not prove their caption appearance.
